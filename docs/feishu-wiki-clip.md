# 飞书知识库剪存

质量优先级依次为：原文内容一致、排版便于阅读、处理速度。用户提供的文章作为回归样本，修复应落在共享保存流程或站点结构适配上，不能为文章 ID 或标题设置特例。受支持的正文、结构和图片须核对通过后才报告成功；无法完整转换的内容明确提示，不静默删减。范围选取、转换覆盖、目标回读及中断恢复都属于验收边界。

## 用户流程和范围

在原网页打开插件，通过当前页主操作旁的“保存到飞书”进入剪存页；所有分类都提供入口。网页地址和来源标签页自动带入，复用飞书登录，选择知识库和父页面，每篇网页保存为该页面下的独立子文档。可以粘贴父页面链接，也可以浏览自己的知识库目录；确认位置后立即持久化，下次打开自动校验并使用，无需重新输入或确认。校验失败不会覆盖上次选择，任务中的目标快照和下次默认位置独立保存。

飞书源文档只需当前身份能读取，**不要求原生“创建副本”权限**。正文通过飞书官方文档块 API 读取，图片使用当前浏览器登录态从飞书正常图片查看器的原图预览地址下载；新建自己的文档，重建正文并上传独立图片，核对后迁入所选位置。原文不会被移动或修改。目标页面需要允许新增子页面，保存文档的可见性由目标知识库权限决定。

新保存的文章在标题下、正文前增加一行“原文出处：来源域名 · 查看原文”，点击“查看原文”返回此次保存的原始网页或飞书文档入口。来源行使用普通正文段落，不进入目录，不额外插入空段或改变正文顺序；URL 不用新建副本地址替代。网页使用快照的 `source_url`；飞书来源由 `prepare_content` 的 `origin_url` 保留用户的 wiki/docx 入口（旧调用者省略时使用源 docx 地址）。来源行随首批正文写入并参与完整回读核对，只有首批已满或以独立书签卡片开头时才另用一个小批次，不额外请求原站。其标识和链接记入本机计划，重试和重启复用同一行；已有旧计划与已保存文档保持原样，后续新建任务自动带上来源。

保留标题、富文本样式和链接、段落顺序、多级标题、列表、代码、引用、分隔线、普通表格、图片位置和尺寸。普通 API 的 `999` 块先通过 CLI `docs +fetch --api-version v2` 定位：文档顶层的原生网页书签卡片通过 v2 XML 按原位置重建，并回读核对标题与链接。没有 AI 摘要、改写或 Markdown 中转。评论、历史版本不复制。合并单元格、其余未知资源块、嵌套书签、非文本行内资源等暂不支持，准备阶段会明确停止，不会静默丢弃内容。最大 10000 块，每张图片最大 20 MiB；单个根子树不能超过接口单批 1000 块或 20 张图片限制。

编辑器遗留的空引用框会保留容器并补入一个空段落，满足创建 API 对子块的要求；不增加可见正文，也不删除原有引用框。最终核对数量包含这些空段落。书签除写入后立即核对，还在正文和图片全部完成后再次通过 v2 核对。

其他网页使用当前已打开的页面正文快照：生财文章定位 `main .content-container`，同时涵盖导语 `.post-content` 和所有嵌入的 `.feishu-doc-content`；旧页面只有一个正文区域时兼容直接选取。若任何可见的已知正文区域位于所选范围外，明确停止，不能把范围内转换成功当作全文完整。自身或祖先隐藏的备用区域不参与此检查。公众号定位 `#js_content`，普通文章复用现有正文提取器，Google Docs 仍走原生 HTML 导出。保留标题层级、富文本、正文、列表、普通表格、引用、代码与图片位置。视频、音频和附件卡片保留名称及可用 HTTP(S) 原链接，不下载媒体或附件文件；无直链、blob 或 data 占位地址时，明确输出“在原网页播放/下载”的来源链接，有实际 DOM id 时保留定位锚点。生财 `.block-file.video/.audio` 按完整组件识别，只排除标题图标和播放按钮，其他正文图片保留；`.docx-file-card` 的图标、类型提示及下载箭头不当作正文资源。网页图文读取期间保持原标签页打开，首次快照落盘后重试复用同一内容，不重新抓取已变化的页面。画布、公式、合并单元格等其余未支持资源仍明确停止。网页快照最大 5000 块、700 KiB（含内嵌图片）；图片上限同上。

正文读取最多等待 15 秒，并要求内容和图片地址稳定 750 毫秒。生财文章不会回退到整页 `body`；导语和每个嵌入正文分别检查加载、登录及 busy 状态，前言先出现不能掩盖正文仍未加载。隐藏的备用区域不参与等待。读取期间网址变化会停止，回到原文章后可继续同一任务。长代码块和长段落保留在原块内，文字片段按最多 2000 字符拆分，不再对整个块施加 10000 字符限制；快照总量限制仍有效。

媒体克隆保留浏览器实际选中的 `currentSrc`，避免多个 `<source>` 中第一个格式不可播放时保存错误地址。捕获接口为 v5；已注入旧版的源页面会替换捕获方法，原本地导出消息监听器保持一个。再次注入同版本不重复注册。附件卡中的额外正文图片、媒体和第二个名称也保留，只有明确的类型徽标、操作提示和箭头作为装饰排除。读取、转换和图片失败的具体原因显示在主状态区域，错误码留在详情；尚未创建文档时不会声称已经保存正文或文档。

浏览器读取网页图片，跨域请求不携带页面凭据。遇到 CORS 限制，仅在扩展已拥有图片域名访问权限时使用后台无凭据请求，不扩展主机权限。仍无法取得图片时停止，不能跳过图片并宣称完整保存。飞书源文档还需 CLI 身份能读取；网页来源不需要飞书账号拥有源网站权限。保留内容和结构不等于逐像素一致，飞书会按当前编辑器和窗口宽度排版。独立电子表格和多维表格不在此流程内。

所有网页图片都区分资源像素和文档显示尺寸：下载后实际解码取得 `pixel_width/pixel_height`，随图片分块暂存，不使用懒加载占位图或尚未加载的 `naturalWidth=0` 决定最终排版。图片文件不重编码、不二次压缩；按比例适配最大 720px 正文宽度，作者明确设置的较小宽度和本来较小的图片不放大。网页快照的 `images[].display_width` 只表示布局意图，不混入飞书图片块。读取的仍是源网站提供的图片地址，不据此宣称取得上传者原始文件。飞书源文档复制沿用其原有宽高与 `scale`。

生财的重点提示框按原位置、子块顺序、背景色和边框转换为原生 callout。只有完整图标确认为官方支持的 💡/✅/📝/📌/❗/🎁 时才用原生 emoji 字段表示，避免额外生成孤立图标段落；未知图标以引用容器保留原图标和正文，不猜测或替换。此规则针对站点结构，不按文章 ID 或标题分支。

注入函数在页面内捕获异常，以 `{ok, data, error}` 结果传回扩展；不能依赖 Chrome 将注入函数的异常转成 `executeScript` 的 rejection。正文、网页图片和飞书图片共用该传输方式，原始错误得以显示，图片 CORS 错误也能进入已有权限下的后台回退。

已有连接和默认位置时，主路径是确认文章与位置、点击一次“保存到飞书”，之后后台完成并通知；成功按钮直接打开飞书结果。来源输入、目录选择、诊断详情和停止操作默认收起。恢复完整默认位置只查询连接状态和父节点，知识库列表在用户展开目录选择时才读取。

保存主区域始终显示“读取图文 → 写入并核对 → 保存到知识库 → 确认完成”，高亮当前阶段并标记已完成阶段，每 2 秒同步后台状态。阶段内展示具体操作和真实进度：读取图片按张计数，写入与核对按连接器返回的累计处理项计数（含正文批次、图片上传与关联等），不是整篇保存百分比；无有效总量时只显示等待条。每秒更新自任务开始经过的时间和最近任务活动时间，刷新页面沿用持久时间。排队、自动重试及延迟查询分别提示；任务 30 秒无活动时提示等待较久但不判定失败，状态读取失败或 15 秒未收到状态时明确提示无法确认最新进度。进度展示不触发新建或重试操作，只有最终位置核对通过后才显示全部完成。

网页剪存默认优先保留内容和结构，并采用飞书原生阅读间距。普通正文中完全空白或只有单个 `<br>` 的无标记段落作为编辑器占位间距，在生成写入批次前省略；不合并非空段落。列表、引用、表格和明确的预格式区域内保留必要空段，但使用真正的空段落，避免把占位 `<br>` 转成两行。正文内部和单段多个 `<br>`、代码中的缩进及空行、非断行空格都保留；有锚点或可识别背景样式的空段不按普通占位段丢弃。全页编辑器继承的 `pre-wrap` 与局部作者指定的预格式区域分别处理。

捕获克隆携带实际的文字颜色、背景色、对齐和空白模式；颜色映射到飞书预设色系，普通深色正文随飞书主题显示。颜色并非任意 RGB 的像素级复刻，网页字体、宽度和 CSS 段间距仍适配飞书。转换完成后独立遍历源 DOM，检查可见正文文字和图片是否恰好被处理一次；未识别结构内遗留的实质内容会停止保存。再检查生成的段落可达性和输出文字顺序，已有飞书回读继续校验快照中的文字、换行、样式、图片和位置。该转换检查不发起网络请求，不用 AI 改写，不增加保存确认。源范围检查、转换覆盖检查和目标回读各自负责不同边界，不能相互替代。已暂存的正文快照和已完成文档不自动重排或覆盖。

生财列表中的 `.bullet > .bullet-dot` 单个圆点在列表正文外时，由飞书原生列表表示，不计为漏存文字；同节点包含额外文字或图片时仍停止保存，列表正文内的同名节点正常保留。读取原文阶段的完整性错误直接显示具体原因和“重新读取并保存”，已创建文档的核对失败继续显示保留文档与进度的恢复提示。回归包含真实圆点 DOM 结构及故意混入正文、图片的反例。

## 一次性连接

普通 Mac 用户可在首次连接页面点击“复制安装提示词”，交给本机 Codex、Claude Code 或 WorkBuddy 执行。商店安装用户无需手动克隆仓库。固定源码下载、依赖、校验及验收步骤见 [Mac 快速连接](connector-setup.md)。下方保留已有依赖的源码安装说明；Windows 飞书剪存暂不支持，Linux 不作为当前上手流程的验收目标。

当前版本通过本机连接器调用官方 [飞书 CLI](https://github.com/larksuite/cli)，扩展不保存应用密钥或登录令牌：

`剪存页 → 扩展后台 → Native Messaging → 本机 lark-cli（用户身份）→ 飞书官方 API`

本机需要 Python 3、Node.js 和已配置的 `lark-cli`。从项目根目录加载扩展后，运行剪存页显示的命令：

```bash
python3 helper/install_feishu_native_host.py --extension-id <当前扩展ID>
```

默认 Chrome；Dia 加 `--browser dia`，Edge 加 `--browser edge`，Chromium 加 `--browser chromium`。支持 macOS / Linux，Dia 仅 macOS，Windows 暂未支持。Dia 的注册目录为 `~/Library/Application Support/Dia/NativeMessagingHosts/`，与 Chrome 独立。连接器只注册所给扩展 origin，不启动 HTTP 端口。安装成功打印 manifest、launcher 和状态目录。扩展应加载项目根目录，不能加载旧 `release-cws/`。更新后刷新扩展和源网页。

现有配置与扩展 ID / 路径冲突时安装器停止，明确使用 `--force` 才覆盖连接配置；恢复记录保留。项目路径或 Python / Node 安装位置变化后重新安装连接器。

| 平台 | 本机状态与连接器位置 |
| --- | --- |
| macOS | `~/Library/Application Support/FeishuClipper/native-host/`；浏览器 `NativeMessagingHosts/com.feishu.clipper.json` |
| Linux | `~/.local/share/feishu-clipper/native-host/`；浏览器 `~/.config/<browser>/NativeMessagingHosts/com.feishu.clipper.json` |

安装后重新打开剪存页或点击“重新检测”，优先复用本机已有授权。连接成功时收起首次连接说明、隐藏登录按钮，直接显示可用状态。仅首次未登录、授权失效或缺少新增权限时显示登录入口；网络错误和本机连接故障不会触发重新授权。首次登录完成官方授权后，再点“已完成授权，继续”。CLI 保管令牌并刷新，临时 device code 只存本机 `0600` 文件，授权完成后清空；扩展只收到官方授权链接。

内容重建与目录操作所需 scopes：

```text
wiki:space:retrieve wiki:space:read wiki:node:retrieve wiki:node:read
wiki:node:move docx:document:readonly docx:document:create
docx:document:write_only docs:document.media:upload space:document:retrieve offline_access
```

当前连接器保留旧原生副本任务的恢复接口。新任务不经过复制权限预检，默认登录也不申请仅旧复制路径使用的权限。

`space:document:retrieve` 用于核对云空间根目录中的本次随机保存标记。新建前先读取目录确认权限可用，缺少权限时在产生文档前提示。仅查看文档元数据，不读取不相关文档正文；此次实测当前用户已有授权可读取该接口，无需重复登录。

面向普通用户分发时，建议改为托管 OAuth 授权服务，实现“登录飞书 → 选择位置 → 保存”，免除本机 CLI 安装。当前交付是可本地使用的连接器版本，尚未部署该服务。

## 模块和接口

| 模块 | 职责 |
| --- | --- |
| `feishu-save.html/js/css` | 登录、目录选择、默认位置、进度和恢复 |
| `shared/feishu-wiki-clip.js` | 内容收集、重建、迁入及位置核对状态机 |
| `shared/feishu-image-capture.js` | 在准确飞书源页面中读取图片，不传出凭据 |
| `shared/web-feishu-blocks.js` | 网页 DOM 转飞书块，拒绝不完整内容 |
| `shared/web-image-capture.js` | 网页图片读取、类型/大小检查和字节保留 |
| `shared/feishu-clip-service.js` | 验证扩展页面消息来源、逐篇持久队列、原生请求串行执行及结果通知 |
| `helper/feishu_native_host.py` | 固定业务白名单、CLI、字段过滤、本机恢复记录 |
| `helper/feishu_content_import.py` | 源快照、图片分块、分批重建和全量内容校验 |
| `helper/install_feishu_native_host.py` | 按指定扩展 ID 注册连接器 |

所有 API 使用 `--as user`；wiki 源先解析实际 docx token。

| 步骤 | 官方 API（省略 `/open-apis` 前缀） |
| --- | --- |
| 知识库及目录 | `GET /wiki/v2/spaces`、`GET /wiki/v2/spaces/{space_id}/nodes` |
| 我的文档库 | `GET /wiki/v2/spaces/my_library?lang=zh` |
| 解析父页面和 wiki 源 | `GET /wiki/v2/spaces/get_node` |
| 原文标题和结构 | `GET /docx/v1/documents/{token}`、`GET /docx/v1/documents/{token}/blocks` |
| 新建自己的文档 | `POST /docx/v1/documents` |
| 查证本次新建结果 | `GET /drive/v1/files`，根目录按随机标题精确匹配 |
| 恢复原文标题 | `PATCH /drive/v1/files/{token}?type=docx`，`new_title` |
| 分批写入结构 | `POST /docx/v1/documents/{token}/blocks/{token}/descendant` |
| 独立图片资源 | `POST /drive/v1/medias/upload_all` |
| 图片绑定和格式 | `PATCH /docx/v1/documents/{token}/blocks/batch_update` |
| 迁入新文档 | `POST /wiki/v2/spaces/{space_id}/nodes/move_docs_to_wiki`，`apply=false` |
| 异步迁入结果 | `GET /wiki/v2/tasks/{完整task_id}?task_type=move` |

图片下载使用正常图片查看器的 `download/preview/{token}/?preview_type=16`，并检查实际像素，防止预览缩略图混入。读取的是浏览器可访问的完整分辨率图片；不据此宣称与原始附件文件逐字节相同。连接器只处理固定业务动作，不接受任意本机命令或路径。`prepare_web_content` 仅由扩展后台调用，接收 `{operation_id, source_url, snapshot?}`；首次快照严格校验 `{title, source_url, blocks, images}`、块类型、树结构、图片绑定、大小和 URL 协议。省略快照只恢复匹配操作和网址的已有记录，否则返回 `IMPORT_NOT_PREPARED`。图片网址只回传浏览器读取，本机不会对快照网址发起请求。网页内容脚本无权向连接器发起写入。不会调用审批申请、删除或消息发送接口。

## 数据完整性与恢复

1. 读取源文档前后比较 revision，按根 children 遍历，拒绝缺失块、循环、重复或不支持的资源。
2. 全部图片先下载并暂存，校验实际像素、类型、分块内容和 SHA-256，再新建文档。正文与图片在本机权限受限的状态目录保留，供中断恢复。
   图片上传响应丢失时可有限重传同一哈希的素材，最多三次，只绑定已确认的 token；可能留下未绑定素材，但不会新增文档或重复正文。计数跨重启保留，达到上限后停止，完整性核对仍必须通过。
3. 新建前持久化随机标记、操作意图和查证期限，以“飞书剪存-随机UUID”暂作标题，成功后保存新 token。结果不明不自动重发：自动列举根目录，精确匹配随机标题，再分别核对文档 ID、标题和唯一空根块，确认后沿用该文档继续。目录没有匹配项不能证明创建失败；多项匹配、标题变化或非空文档都不能认领。正文完整核对后恢复原题，再回读标题并迁入。每个 descendant 批次使用持久 UUID `client_token` 幂等恢复。
   原生书签通过 v2 `append` 单独成批，写入前记录意图。写入后核对根块顺序及卡片 XML，再推进正文；响应丢失时只读取已追加的位置恢复，不重复追加。
4. 每次 `import_step` 最多发起一次远程请求。重建块、上传图片、绑定 token、逐页读取新文档都可续接同一操作 ID。
   图片逐张上传并落盘记录，再按最多 20 张合并为一次绑定请求，遵循接口资源数限制。批次的完整请求体及 `client_token` 在发送前持久化，断连后原样重放；旧版尚未确认的单图绑定仍复用原请求，已绑定图片不重传或自动改尺寸。尚未重载的旧扩展可继续使用不带像素字段的分块协议，完整后从实际暂存文件恢复宽高；只提供一项、非法值及前后尺寸冲突仍拒绝。旧网页任务缺少像素元数据时，先核对暂存文件 SHA，再从文件头恢复宽高；不能确认时停止，不能接受默认 100×100 并报告完整成功。
5. 将明确指向原文已知章节的内部链接改到新文档对应段落，外链保留；逐块校验类型、富文本、段落与子块顺序、表格属性、图片的新 token 和尺寸。核对失败保留新文档，不能当作完整结果迁入。
6. 连接器只允许迁入 journal 证明由本次创建、内容核对通过的文档。迁入后核对文档 token、知识库、父页面及普通节点类型，全部吻合才显示完成。
7. 迁入任务状态 `1` 为处理中、`0` 为成功、`-1` 为失败，完整任务 ID 按字符串保存。可继续迁入同一份文档，也支持手动移动后再次核对。

内容核对会补齐飞书接口省略的已知默认值：表格 `header_row/header_column=false`，文字块的 `align=1`、`done/folded/wrap=false`。只接受文档定义的默认表示等价；实际标题行设置、正文、空白、图片和非默认格式变化仍然拒绝。

### 自动恢复

生财文章中的 `headPc + head_img + aHref` 人物提及组件保存为原句中的显示文字和链接，头像不作为正文图片下载；缺少显示文字或结构不完整时明确报告，普通图片规则不变。旧版误将成员 ID 解析成文章路径下的图片网址时，连接器仅对尚无任何图片文件、上传或新建进度的任务返回 `refresh_required`；状态机自动重新提取源网页，再调用 `refresh_web_content({operation_id, source_url, snapshot, request_id})`。新快照通过完整校验后备份旧快照、持久记录替换意图并继续原任务；同一请求去重，中断后先完成本地替换。已写入或有图片进度的快照不能覆盖。

本机连接器仅为确认可以安全重试的错误返回 `retryable: true`。暂时的服务错误、限流和读请求超时会按具体操作判断；正文追加和图片绑定依赖持久化 `client_token`，响应丢失时重放同一幂等请求。新建文档结果未知、权限问题和内容差异不自动重发。迁入已知副本使用下述独立恢复契约；本机连接器断连时也由该契约恢复，其他未确认写入不会被猜测为可重试。

新版新建响应丢失时返回 `content_recovering` 和 `deferred_until`，后台按 1、2、4、8、15、30 秒间隔自动查证，最多等待 5 分钟；等待期间释放执行槽供其他文章保存。恢复后继续同一操作，绝不以新操作 ID 替代。旧版没有随机标记的未知创建仍保留并明确报告未确认；没有匹配项、到期或目录缺失都不能作为重发新建的依据。接口依据：[创建文档](https://open.larksuite.com/document/server-docs/docs/docs/docx-v1/document/create.md)、[列举文件](https://open.larksuite.com/document/uAjLw4CM/ukTMukTMukTM/reference/drive-v1/file/list.md)、[更新文件元数据](https://open.feishu.cn/api-explorer?from=op_doc_tab&apiName=patch&project=drive&resource=file&version=v1)。

扩展持久保存 `feishuWikiClipJobs` 队列，兼容旧的当前任务与历史记录。每次插件入口生成新的 `requestId`，同一文章也可独立保存；默认目录与已有登录可复用，历史任务不会成为新请求的状态。同一 `requestId` 的重复消息仅对应一个任务；刷新页面保留 URL 中的请求标识，更换文章或目标生成新标识。页面按 `requestId`（或通知携带的明确 `jobId`）查询，继续/结束按任务 ID 定位。暂停、失败或等待恢复不会锁住后续任务。所有 Native Messaging 请求（含页面只读查询）串行执行，避免连接器进程锁冲突。短时查证使用单个定时器，浏览器 alarm 负责 worker 回收和重启后的恢复。

迁入知识库由 `move_doc` 统一管理：先持久化文档与目标及迁入意图，返回 `wiki_token / task_id / deferred_until`。响应丢失或进程中断后按 `obj_type=docx` 和本次 `obj_token` 查询实际节点；已在目标则写回 `moved`，未查到且没有已知异步任务时，在再次确认父页面后仅重发同一文档、同一目标的迁入。官方 [迁入 API](https://open.feishu.cn/document/server-docs/docs/wiki-v2/task/move_docs_to_wiki) 明确已完成或已在 Wiki 中时返回 Wiki token，这一语义仅适用于已知文档迁入，不适用于新建。查询网络错误不会被当作未迁入；[节点查询](https://open.feishu.cn/document/server-docs/docs/wiki-v2/space-node/get_node) 返回的文档、知识库、父页面与节点类型必须全部匹配。

迁入恢复的 15 分钟期限、退避时间及最多 5 次 POST 计数写入 journal，重启不重置。已有 task_id 只查询该任务；处理中返回延期让出队列。临时读错延迟后继续；429 尊重返回的等待时间；131007 按官方要求禁止重发，只允许查询已完成结果。明确权限/位置错误、任务失败或恢复到期才停止并通知。初次返回的 wiki_token 也须实际读取位置后才能记为 `moved`。扩展最后再确认位置并通知成功。旧版暂停的迁入任务只在同操作的来源、副本、目标、内容完成标记和 helper 恢复声明完全匹配时升级一次；用户主动停止、明确失败或过期任务不会被重新启动。

用户明确点击“重新保存到飞书”时，浏览器先持久保存该次 `request_id`，再调用 `retry_content_creation({operation_id, request_id})`。连接器仅对尚无文档 token 的失败创建开启新尝试，保留正文、图片和旧尝试摘要；同一请求重复传输或重启不会再重置新尝试。这个动作不会由 alarm 或自动恢复调用，不追加确认弹窗。旧无标记任务不再提供没有实际查询能力的“重新核对”按钮。已完成的精确 journal 也允许补回浏览器因断连漏收的副本 token，仍需来源、目标、内容完成标记与真实知识库节点全部匹配。

后台对同一步按 1、2、4、8、15 秒等待并重试，最多 5 次。任务保留 `autoRun`、重试次数、下次重试时间、错误码与失败步骤；界面显示自动恢复进度。通过 `chrome.alarms` 每 30 秒检查尚未结束的自动任务，service worker 重启后恢复同一操作 ID 和剩余重试预算；重启不是重新创建任务。Chrome 可能延迟 alarm，因此后台被终止后的恢复并非立即发生。保存页的连接和目录只读请求遇到暂时繁忙，会单独按 1、2、4 秒最多重试 3 次。授权请求不会自动重试。

完成、手动结束、达到重试上限或遇到不可重试错误后关闭该任务的自动恢复；队列中没有自动任务才清除 alarm。新任务自动处理，异步迁入仍在运行时自动查询。读取图文前半段仍需保留源网页。连接器在原有状态目录内保留最近 20 条失败的操作、阶段、错误码和时间，不记录原始 CLI 输出、凭据或正文。

后台初始化和保存页首次打开时，自动核实已经报错暂停、且有副本的旧内容任务。本机新增 `get_operation({operation_id})` 只读动作，返回该任务的源标识、来源网址、副本标识、内容核对标记、目标位置和已确认的迁入节点，不返回正文、图片或凭据，不调用写入接口，也不修改任务记录。只有本机证据与浏览器任务全部匹配，并再次通过 `get_node` 核实飞书当前位置后，才同步为完成。普通进度轮询不重复发起核实；旧暂停迁入按上面的严格恢复条件升级一次，其余未完成或证据不匹配时保留原状态，不把内容差异当作可重试写入。其他文章始终可以独立保存。

内容和位置核对完成后，保存页显示绿色勾和固定的“总耗时”，由任务创建时间与最终核对完成时间计算，包含排队、自动重试与恢复等待；刷新不会继续增加。旧任务缺少可靠起止时间，或只读恢复只能证明已完成而无法还原完成时刻时，仅显示核对结果，不推算耗时。

保存页在后台完成时，标签页图标变为绿色圆形白勾，标题为“已完成 · 文章名”。用户回到前台并显示该任务的完成结果后，恢复原图标与“剪存 · 文章名”。已读凭据按任务单独保存于 `feishuClipComplete:<jobId>.viewedAt`，与运行中的任务记录分开；后台轮询不会标记已读，刷新、重启或其他任务的完成不会重新点亮已读标识。

后台使用 `chrome.notifications` 发送一次静默成功通知，包含文章及可靠总耗时，点击打开对应知识库副本并标记已读。若对应任务的保存页正在聚焦窗口的活动标签页中，先抑制通知，待页面渲染完成后确认已读；若在确认前离开或关闭页面，补发通知，焦点事件仅重试通知，不恢复文档写入。完成确认会清除该任务现有通知。扩展沿用 `notifications` 权限，本地保存通知对应任务与结果，刷新或重启时去重。关闭保存页不影响发送；通知失败不改变任务的成功结果。操作系统或浏览器禁用通知时可能没有桌面横幅，保存页仍可查看结果。接口依据：[Chrome notifications](https://developer.chrome.com/docs/extensions/reference/api/notifications)。

后台实际执行后最终失败或耗尽重试时，发送“这篇文章暂未保存完成”通知，点击返回对应来源与目标的剪存页。临时重试和延迟查证不发送失败通知。通知意图与失败状态同时持久化，worker 重启后续发；同一任务、错误码和失败步骤去重。升级前的历史失败没有通知标记，不会突然补发。

扩展保留任务队列、默认位置及历史兼容记录；不会将正文存入扩展 storage。正文快照、图片和操作 journal 留在本机连接器状态目录，完成或结束任务后不会自动删除，用户可自行管理。结束任务不会撤销飞书已接收的操作，已有文档仍保留。
