# 公众号按日期下载（TikHub）

输入同号任意一篇公开文章及日期范围，扩展通过 TikHub 逐页获取历史列表，下载所选文章前核对原文发表日期。先在插件中查看账户、日期和文章标题，点击标题打开原文，勾选后再下载本地 ZIP 或逐篇 Markdown。不需要公众号后台登录。

## 本机配置

仅 Mac 本机连接器路径已验收。项目根目录 `.env` 支持 `tikhub_api_key` 或 `TIKHUB_API_KEY`；不要把密钥写入扩展文件、浏览器 storage 或截图。`.env` 已加入 Git 忽略。

在源码根目录安装独立连接器，扩展 ID 从 `chrome://extensions` 获取：

```bash
python3 helper/install_wechat_native_host.py --extension-id <当前扩展ID>
```

连接器注册为 `com.wechat.clipper`，不更改 `com.feishu.clipper`。它从当前源码目录加载 Python 模块及 `.env`，不启动 HTTP 端口，不需要第三方 Python 依赖。安装器遇到不同的已有配置会停止而不覆盖。

本次已为当前 Chrome 扩展 `ikcjafeibkjmmldmkigaofmjcanjoiib` 安装连接器，源目录即本仓库。现有 Chrome 配置中该扩展也指向本仓库；该已打开浏览器的扩展重载未验收。独立 Chrome for Testing 已加载更新源码并完成真实 Native Messaging、API 与下载测试。

更新后从文章页打开插件，在“批量与专栏工具 → 公众号”填日期，点击“获取文章列表”。查询本身不创建下载任务；在结果中勾选文章，再点击“下载所选 N 篇”。本流程有独立的本地格式选择，默认 ZIP，即使首页默认位置为 Obsidian 也不写入该目录。“检查下载连接”仅检查本机配置，不请求收费列表。修改源码后需刷新扩展及源网页；本机连接器下一次启动直接读取更新模块。

## 时间、分页与恢复

- 固定调用 `POST /api/v1/wechat_mp/v2/fetch_account_articles`，`raw=true`、`item_show_type=0`，只下载图文栏目。
- 简化响应的 `create_time` / `update_time` 是素材时间，不能作为发表日期。优先读取原始图文 `appMsg.detailInfo[].sendTime`，同组多篇全部展开。旧页缺少该字段时使用消息 `baseInfo.dateTime` 做候选筛选，同时核对日期边界相邻一天；命中文章以原文 `ct` 为准。消息时间与原文差异超过一天时中止。二者都缺失时从原文核对，无法核对则中止。
- 日期包含开始、结束当天，时区固定为北京时间。校验目标 `gh_`、`biz`、原文 `mid/idx/sn`，拒绝串号、跳转到另一篇或发表时间不符。
- `next_offset` 原样传回；只有 `is_end` 才确认列表收集完成，短页和跨页乱序不作为结束依据。完整性仅指当前供应商返回到末页的图文列表，不能证明微信已删除或未被供应商收录的内容也可获得。
- 每次最多读取 20 页。未完成、超时、余额/认证错误或游标异常均保留文章进度和待处理页，不宣称完整；已获取的候选文章仍可查看、勾选和下载。再次点击相同链接和范围可续查；没有自动重发收费请求。
- 本机单页请求缓存 5 分钟；扩展按公众号持久保存历史索引，完整索引跨日期范围复用，不因 5 分钟过期重新收费。旧范围查询的有效快照和游标自动迁移，原记录保留。点击“刷新账号历史（重新请求）”才重新扫描；失败续查使用已保存游标，损坏游标明确报错，不静默从头购买。
- 查询期间关闭 popup，后台仍继续收集列表；重新打开会恢复匹配当前账户链接和日期范围的查询状态、列表及勾选。浏览器退出/扩展重载导致查询中断时，再次点击相同范围续查。更改链接或日期会隐藏旧列表，防止使用另一范围的选择。
- 点击下载时固定所选文章、图片和本地格式。后台只接受当前持久化列表内的文章（包括未完成列表），核验所选原文的账号、文章身份及日期后创建任务，不刷新列表或增加收费请求，也不接受 Obsidian 输出目标。关闭 popup 后仍会打开任务页；需保持下载任务页打开。
- 保留微信原文所需的 `chksm` 和 `scene` 及原查询编码；移除 `sessionid` 等跟踪参数。正文、图片沿用插件现有页面与导出逻辑。

TikHub [当前文档](https://tikhub.apifox.cn/472974858e0) 标价 $0.01/次列表请求，按未缓存请求计，单次 20 页约 $0.20 上限，不包含用户再次续查。首次收集及显式刷新仍须覆盖乱序列表，但每页到达即显示命中文章，不再串行打开所有候选原文。后续页失败不会清空已有结果，HTTP 状态及请求耗时会显示；完整缓存筛选日期不产生列表请求。超时可能已被供应商计费，故不自动重试；实际账单以供应商为准。

密钥只用于固定 HTTPS TikHub 请求，禁止携带密钥重定向。扩展只允许自有 `popup.html` 发起历史操作；网页 content script 无权调用付费入口。Native host 仅接受配置的扩展 ID、两个固定 action 及参数白名单，响应/缓存不保留供应商 debug 数据或密钥。

## 输出问题修复

旧范围下载入口继承首页的全局输出位置，界面没有显示该选项，因而可能将用户预期的 ZIP 任务创建为 `outputTarget=obsidian`。新版查询与下载分开，选文入口固定本地输出，默认 ZIP；首页偏好不影响这一入口。

旧任务页捕获 Obsidian 写入异常后仍增加成功数，最终可能出现日志报错、顶部却提示完成。新版按实际输出结果统计成功和失败，并分别展示本地与 Obsidian 的结果；写入失败不能被当作导出成功。
